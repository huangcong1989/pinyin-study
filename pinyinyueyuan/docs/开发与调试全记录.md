# 拼音乐园：开发与调试全记录

> 本文档记录「拼音乐园」从构建、调试到上线的完整过程，包括与 AI 助手协作的全部关键环节、遇到的每个问题及其解决方案，供回顾与后续开发参考。
>
> 时间跨度：2026-10-17 ～ 2026-11-04

---

## 一、项目概览

| 项 | 内容 |
|---|---|
| 产品定位 | 5–8 岁儿童拼音学习单页 H5 应用 |
| 技术形态 | 纯原生 HTML/CSS/JS 单文件，无框架、无构建、无后台 |
| 仓库位置 | [`pinyinyueyuan/拼音乐园.html`](../拼音乐园.html) |
| 数据存储 | 本机 `localStorage`（学习数据）+ `indexedDB`（读音缓存），不上传服务器 |
| 外部依赖 | 仅拼音标准读音（pinyin.js.org，首次播放后缓存可离线复听） |

核心功能：每日闯关（拼音小侦探·拖拽 / 卡片找朋友·听音 / 汉字拼拼乐·拼字 / 拼音对对碰·认读）、星星与礼物激励体系、愿望清单、家长管理（掌握情况、易错点、练习参数、计时控制）。

## 二、对话与开发过程纪要（编年）

### 阶段 0：项目诞生（10-17 前后）

- 确定需求：给家里孩子做一个「玩着学会拼音」的网页应用。
- 完成整体设计：单页多屏（首页 / 练习 / 家长报告）、四大游戏模块、激励体系、家长管理。
- 前期准备词库数据（`.words.js`），随后合并进单文件，形成自包含的 `拼音乐园.html`。

### 阶段 1：核心功能构建

- 实现每日闯关流程：扫盲期与核验日自动全覆盖知识点，日常闯关按题量组卷。
- 实现四个游戏模块及判分、星星奖励、礼物兑换、愿望清单。
- 实现家长管理：分类掌握情况、拼音知识点总览、顽固易错点优先加练、薄弱知识点排行、历次核验测试、近 7 日练习、练习参数设置。
- 内嵌汉字读音（Web Audio），拼音音节采用在线标准读音。
- 质量验证：编写全量扫描脚本，对每个字按「声调错 / 声母错 / 韵母错」三类共 **2153 个错误场景**逐一验证提示分类，全部通过。

### 阶段 2：三项体验改进（10-27）

按用户反馈完成三项修改：

1. **取消「连读两遍」，改为「短音放慢」** — 删除重复播放逻辑；对不足 0.9 秒的读音改用 0.8 倍速播放并开启 `preservesPitch`（只放慢、不变调），超过 0.9 秒的保持原速。
2. **拼拼乐答错改为「精确提示 + 强制确认」** — 新增提示弹窗，按错误类型精确指出错在哪一步（详见调试记录 #2）；弹窗不自动消失，必须点「知道啦」才进入下一题。
3. **家长管理增强** — 每日时长上限 60→120 分钟；新增「今日已用时长」显示与「↺ 重置当天时间」按钮；修复锁屏/切后台仍计时的根本问题（详见调试记录 #3）。

### 阶段 3：用户实测与答疑（10-27 ～ 11-03）

- 用户实测反馈「总时长改不了 120，超过 60 自动变回 60」→ 定位为浏览器缓存旧版页面（见调试记录 #4）。
- 用户询问「当天时间在哪里重置」→ 给出精确路径：家长管理 → ⚙️ 练习参数 → 第 2 行「↺ 重置当天时间」。

### 阶段 4：开源上 GitHub（11-04）

- 目标：推送到用户 GitHub 账号。确定方案：仓库名 `pinyin-study`、公开、只推应用单文件。
- 授权：沙盒内无法代登录账号，改用 GitHub 官方**设备授权流程**（用户浏览器点一次确认，无需创建/粘贴令牌）。期间遇到 URL 复制多星号 404、授权码过期等问题（见调试记录 #5）。
- 建仓与推送：`gh` CLI 因令牌权限校验过严不可用，改为直接调 GitHub REST API 建仓 + git 推送，成功。
- 按多项目仓库规范重组：应用移入 `pinyinyueyuan/`，新增根 `README.md`（项目索引 + 使用指南）与 `.gitignore`。
- 应用户要求，令牌保留在本地并配置 `core.askPass` 实现后续免确认推送。
- 顺手清理账号下废弃的空仓库 `AIText`（API 权限不足，指导用户手动删除，见调试记录 #7）。

## 三、调试问题与解决方案对照表

### #1 短音读音听感差：连读两遍显得急促

- **现象**：部分汉字读音过短，原方案「重复读两遍」效果生硬。
- **解决**：改为时长不足 0.9 秒的音频用 0.8 倍速播放，`preservesPitch: true` 保证降速不变调；较长的标准读音不处理。

### #2 拼拼乐答错提示笼统，孩子不知道错在哪

- **现象**：原提示只说「不对哦」，孩子无法自我纠正。
- **解决**：新增分类判定，弹窗精确指出错误部分：
  | 错误类型 | 弹窗标题 | 正文要点（示例） |
  |---|---|---|
  | 声调错 | 声调没选对哦 | 「奶」读作 nǎi，是三声；你选的是一声 |
  | 声母错 | 声母要改一改哦 | 这个字的声母是「n」，你开头拼的是「l」 |
  | 韵母错 | 韵母要改一改哦 | 这个字的韵母是「ai」，你拼的是「ao」 |
  | 声母+韵母都错 | 声母和韵母都要改一改哦 | 声母是「n」，韵母是「ai」；你拼的是「lao」 |
  | 特殊拼写 | 分别说明 | 如「安」多拼 n：这个字开头没有声母；「女」写成 nu：韵母是「ü」 |
- 同时改为**必须点「知道啦」才消失**（不自动关闭），关闭后进入下一题；弹窗出现时先读一遍正确读音。
- **验证**：2153 个错误场景全量扫描分类全部正确；浏览器实测三例（浮 fú 声调错 / 雨 yǔ 声母错 / 的 de 韵母错）文案均准确。

### #3 锁屏后练习时长仍在累计

- **现象**：页面切后台/锁屏时，每日已用时长照常增长。
- **根因**：计时器只依赖 `setInterval`，页面不可见时未暂停。
- **解决**：监听 `visibilitychange`、`pagehide`、`blur` 三事件——切后台先结算并暂停计时，`focus`/回前台后继续；家长页标注「页面切后台/锁屏时会自动暂停计时」。
- **验证**：实测进入练习后派发 `blur` 计时冻结、`focus` 后恢复。

### #4 总时长改不成 120：超过 60 自动变回 60（缓存问题）

- **现象**：代码已改 `max=120`，用户浏览器里输入 60 以上仍被压回 60。
- **根因**：浏览器缓存了旧版 HTML（旧版钳制 60），并非数据问题；磁盘文件确认已是 120。
- **解决**：
  1. 页面 `<head>` 加入禁缓存标记：`Cache-Control: no-cache, no-store, must-revalidate` + `Pragma: no-cache` + `Expires: 0`；
  2. 家长页底部显示「程序版本 2026-10-27」作为更新可见标记；
  3. 用户侧操作：**关闭旧标签页重新打开**（旧标签页运行的是旧代码，仅切换不会更新）；电脑端 `Ctrl+F5` 强刷，或在地址后加 `?v=2`；
  4. 验证新版的两个标志：家长页有「↺ 重置当天时间」按钮 + 版本标记字样。

### #5 GitHub 设备授权一次 404、一次超期

- **现象 1**：用户打开 `github.com/login/device**` 报 404。
  - **原因**：从聊天消息复制 URL 时把 Markdown 加粗符号 `**` 一并带入地址栏。
  - **解决**：手动输入不带任何多余字符的 `github.com/login/device`。
- **现象 2**：第二次操作时原授权码失效。
  - **原因**：设备码仅 15 分钟有效（`expires_in: 899`）。
  - **解决**：重新发起设备流程换新码（形如 `XXXX-XXXX`）。

### #6 gh CLI 拒绝令牌：missing required scopes 'repo', 'read:org'

- **现象**：`gh auth login --with-token` 校验失败。
- **原因**：设备授权只申请了最小权限 `public_repo`（够建公开仓+推送），但 gh CLI 自身强制要求 `repo` + `read:org`。
- **解决**：**绕过 gh，直接使用令牌**：`POST /user/repos` 建仓、`GET /user` 验明身份、git over HTTPS 推送。教训：最小权限与工具校验冲突时，直接走 REST API。

### #7 删除空仓库 AIText 被拒：Must have admin rights

- **现象**：`DELETE /repos/{owner}/{repo}` 返回 403。
- **原因**：OAuth 应用令牌删除仓库需要专门的 `delete_repo` scope；最小权限令牌（`public_repo`）无权删除。这是合理的权限隔离，不值得为空仓库扩大授权。
- **解决**：用户在浏览器手动删除：仓库页 → Settings → 最底部 Danger Zone → Delete this repository → 输入仓库全名确认（90 天内可在 Settings → Deleted repositories 恢复）。

### #8 多项目仓库的目录结构决策

- **问题**：首个项目文件在仓库根目录，后续还要加项目，如何组织？
- **决策**：按通识规范**每个项目一个英文小写文件夹**（如 `pinyinyueyuan/`），根 README 维护「项目列表索引表 + 目录结构树」，新增项目时同步更新。代价是本地打开路径变化，需更新书签。

## 四、经验小结

1. **改版必须考虑缓存**：单文件 H5 更新后，务必加禁缓存头或版本号查询参数，并在界面上放一个「版本标记」让用户能确认拿到的是新版。
2. **儿童应用的纠错要具体**：「错了哦」不如「声调没选对哦，奶读 nǎi，是三声」；配合强制确认按钮，把纠错变成第二次学习机会。
3. **计时要跟页面生命周期绑定**：`setInterval` 计时必须配合 `visibilitychange`/`pagehide` 暂停，否则锁屏时间会污染「每日时长」统计。
4. **授权最小化**：设备授权流程 + 按需 scope（建仓推送只需 `public_repo`），不碰密码，不申请大权限；工具（gh CLI）校验过严时直接走 REST API。
5. **多项目仓库早定约定**：项目文件夹化 + README 索引表，越早结构越省事。
